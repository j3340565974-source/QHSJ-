# modules/01_script.md — 剧本引擎（物理剧本）

> Skill v1.5.2 原子模块。本文件是剧本任务的唯一入口：把任意形态的输入编译成
> 「物理剧本」——后续分镜、资产、故事板、视频全部环节的唯一事实源。
> 本模块只产出文字交付物，不受美学门约束，但必须通过本模块的剧本质检关。

## 0. 加载契约（按需依赖，进入本模块才加载）

| 依赖 | 相对路径 | 用途 |
|---|---|---|
| 规格常量与画幅/模型 profile | `../shared/standard_specs.md` | 四件套默认值、project_aspect、模型档、提示词 schema 入口 |
| 项目锚点台账 | `../shared/context_ledger.md` | 人物/场景/状态登记，跨任务继承 |
| 原创设计路由（按需） | `../shared/originality_system.md` | 仅用户点名"原创人物/生物/服装/场景/命名/武器/特效/文案/配音"九类时加载 |
| 时长校验脚本 | `../scripts/validate_duration.py` | 台词/钩子时间轴量化校验 |
| 流程校验脚本 | `../scripts/validate_workflow.py` | 六节点闭环与下游依赖校验 |

不加载：美学系统、运镜引擎（图片/视频阶段才强制）。禁止在本模块复制 shared 的默认值。

## 1. 输入（输入兼容层）

接受任意形态：完整剧本 / 大纲梗概 / 一句话创意 / 一段台词 / 一个场景片段 /
已有分镜表（反推剧本）/ 一个关键词。处理策略：

- 完整剧本：诊断 → 补强，重点补缺失场次、改弱台词、加密钩子。
- 大纲/梗概：先补成完整剧本（场次表＋关键台词＋转折），全部补写标【AI补全】。
- 一句话/关键词：从零创作，走本模块完整流程（§3）。
- 一段台词/一个场景：反向推导所属场次，补齐前后场次，再进流程。

HITL 契约（见 `../shared/standard_specs.md` 四件套与台账章节）：先收集用户已给
信息，缺项一次性问清（图片模型/画幅/视频模型/补充说明；纯剧本文字任务可先
记录画幅与模型意向，默认值超时采用并标【参数假设】）；禁止先产出再补问，
禁止重复询问已给信息。

## 2. 裁决基线（阶段一审计，不可回退）

- 剧本是唯一事实源：剧本里没写的物理事实，后面每个环节都会跑偏——先写全，再分流。
- 优先级链：安全 > 用户显式变更 > 剧本事实 > 台账继承 > 模板默认。
- 补写内容一律标【AI补全】；变量从剧本提取，不预设、不强行填默认。
- 反套路黑名单照常执行（失忆、车祸、无理由作妖、结尾梦境等禁用，除非全新处理）。

## 3. 处理流程（十步，顺序执行）

### 3.1 赛道判定
判定赛道 → 锁定受众 → 锁定主副情绪 → 套用心法。判定后必须输出一句：
「本片受众是____，他们看这个是为了得到____。」

### 3.2 Logline（高概念一句话）
公式：一个【有缺陷的身份】+ 陷入【极端处境】+ 必须【高代价行动】+ 否则【最坏后果】。
要求一句话内同时含身份反差＋时间压力＋一个能拍成封面的画面。

### 3.3 骨架选择
从 12 类骨架（绝境逆袭/倒计时/信息差/错位身份/复仇清算/守护救赎/赌局/
规则流/循环/寻人寻物/双强对决/温情反转）选 1 或重组；记下三个必备节点与爆点写法。
不足九个内容节点不硬凑，超出不删减——节点数与后续分镜格数联动，见 02/07。

### 3.4 世界与时间档案（剧本头部必含，六项齐全）
时代背景 / 季节 / 天气（含变化）/ 时间线（总跨度＋每场时刻，精确到光线状态：
清晨薄光·正午顶光·黄昏金光·夜晚人造光）/ 地点总表（场景名＋空间结构一句话）/
周围环境（建筑·自然·声音源·气味源）/ 人物表 / 视觉母题（2–3 个贯穿物件、
色彩、光影或声音母题及含义变化）。

### 3.5 人物事实（身份命名法，铁律）
- 人物因果一律用身份名（张磊、李老师、小偷A、张磊母亲），禁止代词与"男主/女主"。
- 每人一条锁定描述（一句，写在人物表），例：张磊：17岁高中生，黑色短碎发，
  左眉一道浅疤，穿蓝白校服。此描述由 03 模块扩展成角色锚点卡并全项目逐字复用。
- 每人四行：表层欲望 Want / 深层欲望 Need / 恐惧与谎言 / 弧光（从什么状态变成
  什么状态，转折在第几场）。铁律：主角末场必须做出与首场完全相反的选择。
- 每人登记音色锚点（音色类型＋语速基准），供 02/08 台词音色锁定逐字复用。

### 3.6 场次因果链（强制跑通）
每场戏末尾标注：【因果】上一场的__迫使本场发生__；本场的__迫使下一场__。
连续两场填不出因果 → 删场或重写。任何一场都要能回答"删掉这场，后面哪里塌"。
同步维护动作因果链（关键动作有动机）与台词因果链（每句关键台词标【潜台词】
＋【动机】，对话有攻防，禁止社交辞令空转）。

### 3.7 台词系统
台词十诫：像人说话、短句、生活细节、数字具体化、情绪前置、有潜台词；
能画面说不用台词，能动作说不用旁白。反 AI 味红线（"首先其次最后""值得一提"
"命运的齿轮""眼中闪过一丝"等句式）违反即重写，用动作、物件、生理反应替代。
金句规则：短视频每条 ≤1 句放爆发点；剧集全片至少 1 句可截图金句。
台词整改权：不够锋利时大意不变直接整改，标注【原句】→【改句】及理由。

### 3.8 节奏与钩子
- ≤60 秒强制时间轴法则：0–1 秒第一帧即钩子；1–3 秒钩子兑现；3–5 秒立目标给
  阻碍造信息差；15 秒认知反转或情绪升级（硬性）；25–35 秒爆发；最后 3–5 秒
  结尾钩子五选一。每 5 秒一个刺激点，每 10 秒一个转折。
- >60 秒走长片情绪曲线：峰值起步 → 假胜利紧接真失败 → 高潮主动选择＋代价＋
  意象回收 → 结尾 3 秒给结果、2 秒反转、1 秒留白；高强度段落间插呼吸镜头。
- 钩子矩阵全片埋 5–8 个：悬念钩每 30 秒、反转钩每 90 秒、危机钩每 60 秒、
  情感钩每 2 场、信息差钩全片 2–3 个、站队钩结尾前 1 个。铁律：每场最后一个
  镜头必须带钩子（在 02 分镜表"钩子点"列兑现）。

### 3.9 剧情缺口诊断（12 项逐项打勾）
开局 3 秒冲突 / 困境具体可视化 / 反派自认有理 / 信息差 / 每场权力转移 /
假胜利 / 情感锚点 / 最黑暗时刻 / 高潮主动选择 / 续集讨论钩子 / 可删整场 /
可截图金句。任一项缺失进入 3.10 补全。

### 3.10 剧情补全五步法
诊断列缺口 → 按骨架补场次（标插入位置）→ 每场末尾补"方向盘" → 补感官细节
（声音、气味、触感、天气、物件，使场景可拍）→ 补钩子。全部补写标【AI补全】。

## 4. 输出（交付模板）

```
【剧本】
一、故事分析（十问逐问书面作答：核心冲突 / 赛道受众 / Want-Need /
    每场功能与情绪起止 / 权力转移 / 情绪心电图 / 缺什么多什么 / 钩子分布 /
    视觉风格推导 / 可截图瞬间与封面金句对应）
二、世界与时间档案（§3.4 六项）
三、场次因果表
    场号 | 场景 | 时刻+光线 | 天气 | 人物 | 场次功能 | 情绪起点→终点 |
    核心事件 | 权力转移 | 钩子 | 因果链 | 时长预算
四、完整剧本（表演级）
    每场含：物理环境细节（空间结构/陈设/光线/声音源/气味源）+
    人物动作（表演颗粒度对齐 02 的七层结构基准）+ 台词（含【潜台词】【动机】）
五、补全清单（每条标【AI补全】）
```

### 4.1 输出接口：SCRIPT_FACTS（供 02_storyboard.md 消费）

| 字段 | 内容 | 下游去向 |
|---|---|---|
| `project_meta` | 画幅 project_aspect、图片/视频模型、质感基底意向 | 全局（standard_specs 唯一存放） |
| `world_profile` | 六项世界与时间档案 | 02 定场镜头、04 场景事实 |
| `characters[]` | 身份名、锁定描述、Want/Need/弧光、音色锚点、出场场次 | 03 人物卡、02 表演层 |
| `scenes[]` | 场次因果表全字段（含时刻+光线、钩子、时长预算） | 02 拆镜、04 场景路由 |
| `dialogue[]` | 台词 + 潜台词 + 动机 + 说话人 | 02 台词镜、08 音色锁定 |
| `hooks[]` | 时间点 × 钩型登记 | 02 钩子点列 |
| `motifs[]` | 视觉母题与含义变化 | 02 插入镜、07 关键帧 |
| `gap_report` | 12 项缺口诊断与补全结果 | 质检留痕 |

接口写入 `../shared/context_ledger.md`（base_anchor＋state_delta），下游按需读取，
不整包复制。

## 5. 校验（输出前全过）

剧本质检关：
1. 12 项缺口诊断全过；每场因果链填得出；主角弧光成立（末场与首场选择相反）。
2. 世界与时间档案六项齐全；人物全部身份命名并各有一条锁定描述。
3. 台词过十诫与反 AI 味红线；钩子矩阵密度达标；每场末镜有钩子。
4. 时长预算与时间轴法则经 `validate_duration.py` 量化通过。
5. 台账已登记 project_meta / characters / scenes 快照。

脚本校验：`scripts/validate_workflow.py`（六节点闭环与接口字段完整性）、
`scripts/validate_duration.py`（钩子时间轴、台词时长）、`scripts/validate_prompt.py`（接口字段
schema 预检，禁止残留未替换变量与越权字段）。校验最多三轮，仍失败则输出
失败规则 ID 与冲突清单，进入 HITL 暂停，禁止无限循环。

## 6. 边界与禁止

- 本模块不产图片/视频提示词，不调用美学门与运镜（那是 03–08 的事）。
- 不搭售分镜表、资产图等下游交付物；用户只要剧本就只交付剧本。
- 原创设计九板块仅用户点名时经 `../shared/originality_system.md` 路由，不在剧本内搭售。
- 禁止"待补充"式留空：缺什么按 §3.10 补全并标注，不编造与用户设定冲突的事实。
